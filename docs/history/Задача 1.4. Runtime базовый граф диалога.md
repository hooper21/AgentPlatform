ЗАДАЧА: реализуй MafOrchestrationRuntime (реализация IOrchestrationRuntime)
на Microsoft.Agents.AI.Workflows.

1. Граф: DialogExecutor (LLM-ход) → условный переход → ToolExecutor (read)
   → DialogExecutor | GateExecutor (write/destructive) | EscalateExecutor → End.
2. AgentFactory: собирает агента из agents тенанта (промпт, модель,
   активные тулы подключённых коннекторов). Кеш конфига — Redis, TTL 60 с,
   инвалидация при изменении конфигурации.
3. Чекпоинты: после каждого суперстепа state → checkpoints через
   StateContract (НЕ нативные структуры MAF). ResumeAsync восстанавливает
   и продолжает граф.
4. Version pinning: сессия продолжается на версии агента, с которой началась.
5. Для проверки графа сделай тестовый коннектор EchoTools (MCP-сервер,
   тулы echo_read (read) и echo_write (write)) по манифесту.
6. Тест: сессия с рестартом процесса между ходами — диалог продолжается.

## Что реализовано

**1. Граф на `Microsoft.Agents.AI.Workflows` (1.28.0)**

```
turn-start --LlmTurn--> dialog --ToolCall--> tool --LlmTurn--> dialog
     |                    |  \--GateRequired--> gate --LlmTurn--> dialog
     |                    |                     gate --Completed--> end
     |                    |--GateRequired--> gate
     |                    |--Escalation--> escalate --Completed--> end
     |                    \--Completed--> end
     \--GateDecision--> gate (resume после решения по HITL-гейту)
```
Условный переход — типизированные рёбра MAF (`AddEdge<OrchestrationMessage>(..., m => m!.Signal == ...)`). Узлы: `TurnStartExecutor`, `DialogExecutor` (LLM-ход через `IChatClient`, тулы передаются модели **только декларациями** `AIFunctionDeclaration`), `ToolExecutor` (read, с повторной серверной проверкой Policy Engine), `GateExecutor` (pause/resume), `EscalateExecutor`, `EndExecutor`. После каждого узла, меняющего состояние, — чекпоинт.

**2. AgentFactory + кеш конфигурации**
- `AgentFactory` собирает `PlatformAgent`: промпт, модель (`IChatClientFactory` из LLM Gateway), активные тулы подключённых коннекторов (манифест + `tool_settings`, отключённые коннекторы/тулы и повышение политики отсекаются в `EfAgentConfigStore`).
- Кеш: `RedisAgentConfigCache` (TTL 60 с, ключ `agent-platform:agent-config:{tenant}:{agent}:v{version}:g{generation}`, инвалидация — инкремент «поколения», Redis опционален: недоступен → работаем без кеша) и `InMemoryAgentConfigCache` (dev/тесты).
- Инвалидация: `AgentFactory.InvalidateAsync(tenantId, agentId)` — вызывается после сохранения конфигурации (кабинет/Controller).

**3. Чекпоинты и resume**
- Состояние — только нейтральный `SessionState` (`messages, pending_gate, counters, version`), пишется через `StateContract` в `checkpoints` (`EfCheckpointStore`), с номером суперстепа и `graph_signature_hash`; нативные структуры MAF не используются и не проходят валидацию контракта.
- `ResumeAsync` читает последний чекпоинт, проверяет подпись графа и pending gate, восстанавливает состояние и **продолжает граф с gate-узла** (`GateDecision` → tool → dialog → end). approved — вызов тула, rejected/expired/superseded — без вызова, диалог продолжается; destructive-тул подтверждает только оператор.

**4. Version pinning** — конфигурация грузится строго по `SessionContext.AgentVersion` (не по `agents.current_version`), сверяется `config.Version`, при resume pending-тул обязан существовать в закреплённой версии.

**5. EchoTools по манифесту** — манифест вынесен в `EchoToolsManifest.Create()` (используется и MCP-сервером `ConnectorHost`, и тестами); добавлен `EchoToolsInvoker` (in-process вызов `echo_read`/`echo_write`, с пометкой `TODO(2.2) contract` на MCP-транспорт).

**6. Тест рестарта процесса** — `MafSessionRestartTests`: ход №1 в одном DbContext/Runtime, «рестарт» (новый DbContext над той же БД + новый Runtime с пустым кешем), ход №2 — модель получает историю из чекпоинта, счётчики и суперстепы продолжаются.

## Допущения / что осталось за рамками задачи
- `PauseAsync` идемпотентен: чекпоинт паузы пишет gate-узел при `RunAsync`, метод валидирует payload и ожидающий гейт (иначе — `InvalidOperationException`); `approvalId` возвращается в `RunResult.ApprovalId`, запись строки `approvals` делает вызывающий слой.
- `IToolInvoker` — порт; продакшн-реализация (MCP-клиент к Connector Host, лимиты, кеш read-тулов) помечена `TODO(2.2) contract`, сейчас есть in-process EchoTools-инвокер для проверки графа.
- Escalation rules в v1 — только `failed_turns` + `max_turns`/`max_tool_calls`/`max_tokens`; sentiment и др. — отдельная задача.
- Стриминг ответа, маскирование ПДн в LLM Gateway, регистрация Runtime в `Gateway/Program.cs` и Controller-эндпоинт инвалидации кеша — следующие задачи (контракты `IOrchestrationRuntime` не расширялись).
