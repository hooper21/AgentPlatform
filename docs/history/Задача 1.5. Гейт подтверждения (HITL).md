   - отмена сессии в ожидании гейта;
   - изменение конфигурации агента между паузой и resume (version pinning).
4. Карточку возвращай как JSON в RunResult — рендеринг в каналах в фазе 2.

## Что сделано

### 1. Пауза на write/destructive-туле
- `GatePayload` расширен: `tool`, `args_masked`, `human_description`, **`session_id`**, **`created_at`**, `undo_hint`; валидатор требует валидный UUID сессии и метку времени.
- `GateExecutor` при `GateRequired`:
  1. маскирует ПДн в аргументах (`PiiMasker`: email/phone/passport/token/... → `***`), описание тоже строится по маскированным аргументам;
  2. создаёт заявку в `approvals` со статусом **Pending** и `expires_at = now + таймаут тенанта` (по умолчанию **24 ч**);
  3. пишет `pending_gate` (approval id, payload, expires_at, полные аргументы для исполнения) в чекпоинт;
  4. граф завершается — **поток/воркер не удерживается**, подтверждение может прийти позже, в т.ч. после рестарта.

### 2. ResumeAsync
- `Approved` → решение фиксируется в `approvals` **до** вызова, тул исполняется с полными аргументами из чекпоинта, результат уходит агенту, диалог продолжается.
- `Rejected` → тул не вызывается, агенту системное сообщение «действие отклонено», диалог продолжается.
- `Expired` → тул не вызывается, агент получает «подтверждение истекло»; `approved/rejected`, пришедшие после `expires_at`, автоматически трактуются как `Expired`.
- Таймаут: `ITenantGateTimeoutProvider` + `AgentRuntimeOptions.GateExpiry` (24 ч) и `GateExpiryOverrides` по тенанту; фиксируется в заявке при паузе.
- Visitor не может подтвердить destructive-тул: заявка закрывается как `Rejected(system)`, агенту — «требуется подтверждение оператора».

### 3. Edge-cases (юнит-тесты)
- подтверждение после рестарта сервиса (новый Runtime/DbContext/кеш);
- две сессии тенанта с разными ожидающими гейтами (независимые `approvals`);
- отмена сессии в ожидании гейта (заявка → `superseded`, тул не исполняется);
- публикация новой версии агента между паузой и resume (работает version pinning — версия из сессии);
- таймаут 24 ч, переопределение таймаута тенанта, маскирование ПДн, карточка JSON.

### 4. Карточка
`RunResult.GateCard` — JSON (snake_case) карточки подтверждения (`ApprovalCard`: approval_id, tenant_id, session_id, tool, args_masked, human_description, status, created_at, expires_at, undo_hint). Рендеринг — фаза 2.

## Допущения / ограничения
- Полные аргументы для исполнения хранятся в `checkpoints.state` (`pending_gate.arguments_json`), т.к. `approvals.gate_payload` и карточка содержат только маскированные данные; без этого approved-тул нельзя корректно выполнить после рестарта.
- Источник таймаута тенанта сейчас — `AgentRuntimeOptions.GateExpiryOverrides` за портом `ITenantGateTimeoutProvider` (замена на БД-настройку тенанта не потребует изменений `GateExecutor`).
- В DDL `approvals` нет столбца `comment`, поэтому комментарий решения принимается контрактом, но в v1 не сохраняется (расширение схемы — отдельная задача).
- Фонового «свипера» истечения нет: истечение применяется при `ResumeAsync` (включая явный `Decision(Expired, System)`), интеграция с Scheduler — фаза 2.
