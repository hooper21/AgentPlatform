## Что реализовано

### 1. Приём сообщения: `POST /api/sessions/{tenantKey}/messages`
`GatewayMessagePipeline.AcceptAsync` — конвейер: JWT → тенант → rate-limit → визитер → сессия → ход агента → публикация в поток.

- JWT виджета проверяется вручную на `System.Security.Cryptography` (новых библиотек не добавлял): только `alg=HS256`, секрет тенанта, подпись сверяется `FixedTimeEquals`, `exp` обязателен, `nbf` учитывается, clock skew 60 с.
- `tenant_key` берётся из claim; ключ из пути обязан совпасть → токен одного тенанта нельзя применить к эндпоинту другого.
- Секрет — `IWidgetSecretProvider` → `ConfigurationWidgetSecretProvider` (`Gateway__Widget__Secrets__<tenant_id>`), `// TODO(secret-service)` на AES-256 Secret Service и `channels.widget_secret_ref`.
- Тело: `{ "text": "...", "sessionId"?: "...", "channelId"?: "...", "userRef"?: "..." }`. Ответ — `MessageReplyResponse` (`sessionId`, `status`, `outcome`, `reply`, `approvalId`, `gateCard`).

### 2. SSE: `GET /api/sessions/{sessionId}/stream`
- `text/event-stream`, `event: status|delta|gate|done`, flush после каждого события, `X-Accel-Buffering: no`.
- Токен принимается и в `Authorization`, и в `?access_token` (EventSource не умеет заголовки); сессия проверяется tenant-фильтрованным репозиторием.
- `ReplyStreamHub` — журнал событий с replay: подписчик получает накопленный ход и после его завершения; новый ход (`StartTurn`) сбрасывает журнал, иначе вернувшийся визитер сразу получал бы `done` прошлого хода. Завершённые журналы удаляются по TTL.
- Ограничение (честно): `IOrchestrationRuntime.RunAsync` не стримит, поэтому ответ публикуется одним `delta`; токен-стриминг — `// TODO(2.x)`.

### 3. Идентификация визитера
`VisitorIdentityResolver`: JWT `user_ref`/`sub` → localStorage (`X-User-Ref`) → cookie `ap_user_ref` → генерация `v-<guid>`; при новом визите endpoint выставляет HttpOnly/SameSite=Lax cookie. Длина ограничена 200 символами (`sessions.user_ref`).

### 4. Rate-limit тенанта (Redis, token bucket)
- `RedisTenantRateLimiter`: атомарный Lua-скрипт (`HMGET → refill → cost → HSET/PEXPIRE`), ключ `agentplatform:rate-limit:tenant:<id>`.
- `InMemoryTenantRateLimiter` — та же семантика для тестов/dev (`Gateway:RateLimit:Storage=memory`).
- Redis недоступен → fail-open с предупреждением в лог (диалоги важнее лимита). Ответ 429 содержит `Retry-After`.

### 5. Недоступность LLM
- `RetryingChatClientFactory`/`RetryingChatClient` оборачивают `IChatClientFactory` LLM Gateway: `Retries + 1` попыток. Ретраи на уровне вызова модели, а не вокруг `RunAsync` — иначе сообщение визитера попало бы в чекпоинт дважды.
- После исчерпания попыток Runtime возвращает `RunOutcome.Degraded` → Gateway отдаёт fallback «…менеджер ответит лично», ставит `sessions.status = degraded`, пишет ответ в `messages` и в SSE.

### 6. Интеграционный тест
`GatewayMessageIntegrationTests`: сообщение → агент (EchoTools, `echo_read`) → ответ, проверка tool-вызова, сессии, журнала `messages` и SSE-событий; плюс гейт `echo_write`, cookie-идентификация, JWT-`user_ref`, деградация с ретраями, 429.

## Как запустить

```powershell
$env:ConnectionStrings__Postgres  = "Host=localhost;Port=5432;Database=agentplatform;Username=agentplatform;Password=agentplatform"
$env:Redis__ConnectionString      = "localhost:6379"                    # опционально
$env:Gateway__Widget__Secrets__11111111-1111-1111-1111-111111111111 = "<HS256-секрет ≥32 байт>"
$env:Gateway__RateLimit__Storage  = "memory"                            # dev без Redis
dotnet run --project AgentPlatform.Gateway
```
Проверка:
```bash
curl -X POST http://localhost:5110/api/sessions/11111111-1111-1111-1111-111111111111/messages \
  -H "Content-Type: application/json" -H "Authorization: Bearer <widget JWT>" \
  -H "X-User-Ref: visitor-1" -d '{"text":"Привет"}'

curl -N "http://localhost:5110/api/sessions/<sessionId>/stream?access_token=<widget JWT>"
```
JWT виджета обязан содержать `tenant_key` (uuid тенанта) и `exp`, опционально `user_ref`/`sub`.
